## 八、★ 故障演练：数据库不可用时启动 Tomcat 会怎样

### 8.1 为什么要做

手册 S22 特别要求验证三件事，这是第 3 件，原话：

> 把 MySQL 服务停掉再启动 Tomcat，应用会怎样？（连接池初始化失败会不会导致启动失败）

### 8.2 做法（为什么没去停系统服务）

`net stop MySQL95` 需要管理员权限，而当前 shell 非管理员；更关键的是**停用户的系统服务本身有风险**。

改用**等价且零风险**的做法：把**已解包部署目录**里的连接端口从 `3306` 临时改成不存在的 `3399`。

```bash
# 改的是部署产物（webapps/cms-mis/WEB-INF/classes/db.properties），不是源码，也不是库
# 备份 → 二进制方式替换 → 验完立刻还原
```

对应用来说，"连 3399 被拒"和"MySQL 停了"在现象上完全一致（都是 `Communications link failure`），
**验证目标（连接池初始化失败会不会拖垮启动）完全相同**。

### 8.3 实测结果

| 观测点 | 实测 | 判断 |
|---|---|---|
| Spring 根容器 | 17:12:47 `Root WebApplicationContext initialized in 3411 ms` | **启动成功** |
| DispatcherServlet | 17:12:49 `Completed initialization in 1629 ms` | 正常 |
| 8080 监听 | 启动后 **5 秒**内 | 正常 |
| **启动是否失败** | **否** —— 数据库连不上没有阻止容器启动 | ★ |
| 第一个报错点 | 17:13:00 `[pool-2-thread-1]` 排期定时任务 `ArticlePublishScheduler` → `findDueScheduledArticleIds` → `Communications link failure` | 定时任务先撞上 |
| 报错线程 | **`pool-2-thread-1`（任务线程池），不是 `main`** | 所以不影响启动 |
| 不查库的接口 | `health/ping` → 200 `pong`；`system/health` → 200 且 **`status:"UP"`** | 见下方盲区 |
| 查库的接口 | 登录请求**服务端耗时 120003 ms** 后失败 | 严重 |
| 失败异常 | `GetConnectionTimeoutException: wait millis 60001, active 0, maxActive 20, creating 0, createErrorCount 569` | 见下方解读 |
| 客户端侧 | `curl --max-time 110` / `--max-time 200` **两次都没等到响应**（HTTP=000，客户端主动放弃） | 用户侧"转圈卡死" |
| 失败审计 | WebLogAspect 记一条：`结果=FAIL`、`操作人=anonymous(null)`、`参数=[已按配置忽略]`、错误仅异常摘要 | 脱敏与统一错误处理都生效 |
| 响应外泄 | 响应体只有统一错误文案，**无堆栈** | 安全 |
| **日志膨胀** | 8 分钟内 `cms.log` 从 130,218 → 3,625,112 字节，**增量 3.49 MB / 40,270 行** | 约 **430 KB/分钟** |

`createErrorCount 569` 的解读：这是 Druid 后台创建连接线程的**累计失败次数**。
从 17:13:00（首次失败）到 17:17:45（请求超时落日志）约 285 秒，569 × 约 0.5 秒 ≈ 285 秒 —— **完全吻合**，
说明后台线程每约 **500 ms** 重试一次，每次都打一条**带完整堆栈的 ERROR**。

### 8.4 结论

1. **连接池初始化失败不会导致启动失败** —— 因为 `JdbcConfig#dataSource()` **刻意不调用** `DruidDataSource.init()`，
   让 Druid 在首次 `getConnection` 时懒初始化。容器能起，错误在"第一次真正要数据库"时才暴露。
   （这是设计取舍：好处是"数据库可以后启动"，代价是"故障延后暴露"。）
2. **⚠️ 健康检查有盲区**：`/api/v1/system/health` 在数据库彻底不可用时**依然报 `status: "UP"`**，
   因为它只报 JVM/OS 信息，**压根没探测数据库**。拿它当"服务可用性"判断会误判。
3. **⚠️ 失败不是"快速失败"，而是"长时间挂起"**：`druid.maxWait` 默认 60 秒，请求线程被占住；
   登录请求实测服务端耗 120 秒（两次 60 秒等待叠加）才返回。并发几个这样的请求就能把 Tomcat 线程吃光。
4. **⚠️ 日志会被疯狂刷爆**：后台创建连接线程每 500 ms 一条完整堆栈 ERROR，约 430 KB/分钟、**25 MB/小时**。
   无人值守挂一晚就能吃掉几百 MB 磁盘。

### 8.5 容错改进建议（按性价比排序）

| # | 建议 | 做法 | 解决什么 |
|---|---|---|---|
| 1 | 健康检查真探一次库 | `/system/health` 里加 `SELECT 1`，失败返回 `status: "DOWN"` | 消除"库挂了还报 UP"的误判 |
| 2 | 抑制日志刷屏 | `logback.xml` 给 `com.alibaba.druid.pool` 单独设 `level=WARN` 或加重复消息过滤 | 防磁盘被吃光 |
| 3 | 缩短等待 | `druid.maxWait` 从 60000 调到 3000~5000 | 失败快速返回，不占死请求线程 |
| 4 | 要么快速失败，要么启动即校验 | 加 `connectionErrorRetryAttempts` + `breakAfterAcquireFailure=true`；或改成 `@Bean(initMethod="init")` | 让故障"早暴露、可观测" |
| 5 | 定时任务失败告警/退避 | 连续失败达阈值时告警，并按指数退避降低重试频率 | 库长时间不可用时不空转 |

> 📌 建议 1/2/3 改动小、收益大，属于"如果还有时间就做"的项；建议 4 会改变"数据库可后启动"的行为，
> 属于**取舍**，本次演示场景**保留原设计**。
>
> 🔁 **还原**：改回 `db.properties` 后重启（用 JDK 21），实测 `javaVersion=21.0.12.1`、登录 200、列表 `total=20`，应用完全恢复正常。

## 十、本次踩坑记录（都是我自己踩的）

### 10.1 漏设 `JAVA_HOME`，应用跑在 JDK 25 上

第一次做 §8 演练时启动命令没带 `JAVA_HOME`，`system/health` 报 **`javaVersion=25.0.2`**，
与部署基线（`21.0.12.1`）不一致。

- **为什么会漏**：`catalina.bat run` 之前那次是对的，第二次手工敲命令时以为"环境是继承的"。
- **影响**：本次演练的结论（懒初始化、挂起、日志刷爆）与 JDK 版本无关，**结论依然成立**；
  但"跑在哪个 JDK"本身是部署事实，必须一致。
- **修正**：重启时显式带上 `JAVA_HOME="D:\develop\jdk\jdk-21.0.12.1+1"`，`javaVersion` 回到 `21.0.12.1`。

### 10.2 助手脚本文件模式漏选库

`target/dbsql.py` 跑 `s22_clean.sql` 报 `ERROR 1046 (3D000) No database selected`。

- **根因**：脚本的 `-e` 模式带了 `-D cms_db`，**文件模式没带**；而清理脚本里没有 `USE cms_db;`。
- **之前没发现**：因为跑的 `init.sql` 自带 `CREATE DATABASE`/`USE`，恰好掩盖了这个问题。
- **修正**：抽出 `db_name()` 函数（同一个正则取库名），**文件模式也强制 `-D <db>`**。

### 10.3 `docs/接口清单.md` 把受保护端点标成"免登录"

见 §6.3。**根因是断言/文档写错了，不是代码有问题**。
"权限标识：无"被理解成"免登录"，但正确语义是"不校验细粒度权限码，登录校验照常"。
已修正清单并在 §一 1.3 补了"免登录白名单只有 5 条"的说明。

### 10.4 Python 读不到 Git Bash 的 `/tmp` 路径

用 `python -c "open('/tmp/x.json')"` 报 `FileNotFoundError`。

- **根因**：Windows 版 Python 把 `/tmp` 解析成 `C:\tmp`，而 Git Bash 的 `/tmp` 是另一处。
- **处理**：要么用 shell 工具（`head`/`cat`）读，要么让脚本自己用 `urllib` 发请求（校验脚本就是这么写的）。
