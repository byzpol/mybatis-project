## 一、通用约定（所有接口共用，先看这一节）

### 1.1 统一返回体

所有接口返回 `Result<T>`，HTTP 状态码与业务码**同时**设置：

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | Integer | 业务码。成功固定 `200` |
| `message` | String | 提示信息。**成功的 message 固定为「操作成功」**，除非接口显式传了自定义文案 |
| `data` | T | 业务数据，可为 `null`（`Void` 接口即 `null`） |
| `timestamp` | Long | 服务端时间戳（epoch 毫秒） |

```json
{ "code": 200, "message": "操作成功", "data": null, "timestamp": 1780000000000 }
```

### 1.2 双层错误码（**最容易误判的一点**）

| 码段 | 含义 | HTTP 状态 |
|---|---|---|
| `100 ~ 599` | HTTP 语义码（400 参数错 / 401 未登录 / 403 无权限 / 404 / 500） | **同步设置**为对应 HTTP 状态 |
| `10xxx ~ 14xxx` | 业务码（文章、权限、认证等） | **保持 HTTP 200** |

> ⚠️ 因此**不能只断言 HTTP 200**：`11002`（状态非法）、`11003`（水平越权）、`11011`（已归档只读）
> 这些"业务失败"的 HTTP 都是 **200**，必须读 `body.code`。
> 这条在 S16 联调时就踩过（12 条越权与非法流转用例会全部"假通过"）。

文章域常用业务码：

| 码 | 含义 | 码 | 含义 |
|---|---|---|---|
| 11001 | 文章不存在 | 11009 | 版本不存在 |
| 11002 | 当前状态不允许该操作 | 11010 | 乐观锁冲突（并发） |
| 11003 | 只能操作自己创建的文章（水平越权） | 11011 | 已归档，只读 |
| 11004 | 不能审核自己创建的文章（自审） | 11013 | 只有草稿或已驳回可以删除 |
| 11007 | 排期时间非法 | 11014 | 驳回必须填写审核意见 |
| 13003 | 用户名或密码错误（认证域） | | |

**S24 新增四域的业务码**（`ErrorCode` 里本就预留，**本步没有新增任何错误码**）：

| 码 | 含义 | 码 | 含义 |
|---|---|---|---|
| 12001 | 分类不存在 | 12005 | 分类已停用（标签停用也借用此码，见 §五） |
| 12002 | 分类下有子分类，不可该操作 | 12006 | 分类已归档，只读（预留未用） |
| 12003 | 分类下有文章，不可删除（标签被引用也用此码） | 12007 | 已存在同名标签 |
| 12004 | 同级下已存在同名分类 | 12008 | 标签不存在 |
| 14001 | 不支持的报表类型 | 14002 | 报表生成失败 |

> ⚠️ **码段归属**：`12000~12999` 属成员B（分类与标签域）、`14000~14999` 属成员D（日志与统计域）。
> 本步只**使用**既有码，不新增 —— 越界新增会破坏"错误码分段归属"这条组内约定。

### 1.3 认证方式：**Session（Cookie）**，不是 Bearer Token

- 登录成功后服务端写 Session，浏览器带 `JSESSIONID` Cookie 访问。
- 未登录访问受保护接口 → **HTTP 401**，由 `LoginInterceptor` 出（不是权限切面）。
- 已登录但缺权限码 → **HTTP 403**，由 `PermissionAspect`（AOP）出。
- 已登录、有权限但数据不属于自己 → **HTTP 200 + code 11003**，由 Service 层的归属校验出。

> ⚠️ 三级失败形态完全不同，排查时别混：**401 = 没登录 / 403 = 没权限 / 11003 = 不是你的数据**。

**免登录白名单（只有这 5 条，`SpringMvcConfig` 里逐条声明，不用通配兜）**

| 放行路径 | 理由 |
|---|---|
| `/api/v1/auth/**` | 登录/登出本身不能要求已登录 |
| `/api/v1/system/health` | 运维探针，必须能在未登录时判断环境 |
| `/api/v1/health/ping` | 存活探针，给负载均衡/监控用 |
| `/error` | 容器内部错误转发 |
| `/favicon.ico` | 浏览器自动请求 |

> 白名单**按最小必要划**，不是"没写权限码就放行"。所以 `health/page-echo`、`health/require-param`、
> `health/boom`、`health/db-roundtrip` 这四个自检探针**都在受保护范围内**，未登录访问 401。
> 这一点 S22 实测踩过一次（见 `docs/AI应用记录.md` §十四）。

### 1.4 分页参数（继承 `PageQuery`）

| 参数 | 默认 | 约束 | 说明 |
|---|---|---|---|
| `page` | `1` | `< 1` 归一化为 `1`；超出总页数**不截断**，返回空 `records` | 页码 |
| `size` | `10` | `≤ 0` 归一化为 `10`；`> 100` **截断为 `100`** | 每页条数 |
| `sortField` | `null` | **白名单校验**，非白名单列返回 **HTTP 400** | 排序字段 |
| `sortOrder` | `desc` | 只接受 `asc` / `desc`，其它值按 `desc` 处理 | 排序方向 |

分页返回 `PageResult<T>`：`{ records, total, current, size, pages }`。

### 1.5 时间格式

- **请求**（query string 与 JSON body 一致）：`yyyy-MM-dd HH:mm:ss` / `yyyy-MM-dd HH:mm` / `yyyy-MM-dd` 三种写法均可。
- ⚠️ **刻意不接受 ISO 的 `T` 写法**（`2026-11-09T10:00:00`）—— 保持口径唯一，见 §十 的说明。
- **响应**：`yyyy-MM-dd HH:mm:ss`（由 `JacksonConfig` 统一序列化）。

### 2.1 文章域状态机（客户端必须知道的行为约定）

10 个状态：`0` 草稿 / `1` 待编辑初审 / `2` 待主编终审 / `3` 已通过 / `4` 已驳回 /
`5` 已发布 / `6` 定时发布中 / `7` 已撤回 / `8` 已下架 / `9` 已归档。

| 状态 | 允许的动作 | 说明 |
|---|---|---|
| `0` 草稿 | 编辑、提交初审、删除 | |
| `1` 待编辑初审 | 审核 | 编辑 / 主编都可用同一入口 |
| `2` 待主编终审 | 审核 | |
| `3` 已通过 | 立即发布、排期发布 | |
| `4` 已驳回 | 编辑、提交初审、删除 | 驳回理由在详情 `rejectReason` |
| `5` 已发布 | 撤回、下架 | 可再发布（撤回后） |
| `6` 定时发布中 | ——（无人工动作） | **只有定时任务能推进** |
| `7` 已撤回 | 立即发布、归档 | 撤回**可逆** |
| `8` 已下架 | 归档 | ⚠️ **无出边到发布** —— 下架不可逆（手册 F06/S14 写"可重新发布"，与实现不符，以代码为准） |
| `9` 已归档 | ——（终态） | 任何写操作 `11011` |

> 14 条合法迁移全部集中在 `com.lab.cms.common.ArticleStateMachine`，唯一入口 `transfer(status, action)`；
> 各 Service 方法不写 `if-else` 判状态，状态不对时由状态机统一抛 `11002`。

> 3. `parentId=0` 若写成 `> 0` 判断 → "只看顶级"退化为"看全部"。

| E06 | PUT | `/api/v1/tags/articles/{articleId}` | **覆盖式打标** | `category:manage` | path `articleId` + body `ArticleTagBindDTO{tagIds}` | `Integer`（打标后的标签数） | ⚠️ **传的是"最终集合"，未出现的原有标签会被取消**；**空数组 = 清空（合法）**；超 20 个 → HTTP 400；含 `null` → HTTP 400；标签不存在 `12008`、标签停用 `12005` |
| E07 | DELETE | `/api/v1/tags/{id}` | 删除标签（逻辑删除） | `category:manage` | path `id` | `Void` | 仍被文章引用 → `12003`（查**实时 COUNT**，不查 `use_count` 缓存）；删除前**先物理清理同名墓碑**（见下） |

> ⚠️⚠️ **标签域是全项目唯一主动绕过 MyBatis-Plus 逻辑删除的地方**，三处绕行各有硬理由：
> 1. **打标"复活"而不是"重插"**：`uk_article_tag(article_id, tag_id, deleted)` 决定同一对
>    `(文章,标签)` **只能被逻辑删除一次**。直接 INSERT 会在"打→取消→再打→再取消"的第 4 步撞 **1062**。
>    解法：先查**含已删除**的任意一行（手写 SQL，绕过 MP 的 `deleted=0` 自动改写）→ `UPDATE set deleted=0`。
> 2. **删除标签先清同名墓碑**：`uk_tag_name(tag_name, deleted)` 决定同名标签只能被逻辑删除一次；
>    `deleteTag` 前先 `DELETE FROM cms_tag WHERE tag_name=? AND deleted=1`。
>    ⚠️ **这是全项目唯一一处物理删除**，三条纪律写在 `CmsTagMapper#purgeDeletedTombstones` 的注释里。
> 3. **`use_count` 维护用数据库原子增量**（`SET use_count = use_count ± 1`），减法兜 `GREATEST(...,0)`。
>
> ⚠️ 实测发现 `use_count` **与关联表真实值有 6 处不一致**（种子数据本身的问题）。
> 因此定了口径：**展示可以用缓存，保护必须用真相。**

## 九、核对方式与结论（怎么证明这份清单是准的）

### 9.1 生成方式

```bash
# 扫描所有 Controller 的端点 + 权限注解 + 完整方法签名
"C:/.../python.exe" -c "... 见 docs/接口清单.md 的生成脚本说明 ..."
```

脚本逻辑：合并多行方法签名 → 匹配 `@(Get|Post|Put|Delete)Mapping` →
在其**紧随的几行**里取 `@RequirePermission` 与 `@OperLog` → 与类上的 `@RequestMapping` 拼出完整路径。

> ⚠️ **权限注解在 mapping 的下一行，不在上一行** —— 第一版脚本只往上找，
> 结果 16 个端点的 `perm` 全是 `-`。这是"用脚本核对"时最容易犯的错，记在这里。

## 十、与《接口契约》的偏差（**以库表/代码为准**，逐条登记）

| # | 契约 §1.3 写的 | 实际实现 | 原因 |
|---|---|---|---|
| 1 | 列表接口权限 `article:list` | `article:view` | 库表 `sys_permission` 里**没有** `article:list`。照契约写会让所有角色（含 admin）都被 403 |
| 2 | 编辑草稿权限 `article:edit` | `article:update` | 同上，库里没有 `article:edit` |
| 3 | 下架权限 `article:offline` | `article:manage` | 同上，库里没有 `article:offline` |
| 4 | 归档权限 `article:archive` | `article:manage` | 同上，库里没有 `article:archive` |
| 5 | 分页参数未明确非法排序字段的行为 | **HTTP 400**，提示里列出可选列 | 防 SQL 排序注入（实测 `id;drop table cms_article` → 400） |
| 6 | 时间参数格式未明确 | 只接受三种"空格/短横线"写法，**不接受 ISO 的 `T`** | 项目里曾同时存在两条互不相干的 String→时间转换链（`@RequestBody` 走 Jackson、query 走 Spring 默认），S19 统一成一条并刻意不收 `T` |
| 7 | 删除接口未说明可否级联 | **不级联**删除版本与审核流水 | 审计要求：留档优于连坐删除（S18 定的口径） |
| 8 | §5.1 **没有分类/标签/日志/报表四域**（契约是 S03 写的，那时还没计划做这四域） | **S24 补齐 20 个端点**，规格以 §四~§七 为准 | 这四域是"自选加分交付"，不在原契约范围内 |
| 9 | 未说明分类的"层级上限" | **只支持两级**；给二级再挂子级 → **HTTP 400** | 与前端 `ElTree` 的展示层级、面包屑深度一致；三级分类在本项目的业务里没有实际用途 |
| 10 | 未说明"调整分类父级"的语义 | **明确拒绝（HTTP 400）**，不是静默忽略 | 改父级需要**级联更新整棵子树的 `level`**，属高风险操作；且"新建后迁移文章"比"原地改父级"更清晰。**明确拒绝 > 静默忽略** |
| 11 | 未说明标签名的唯一性范围 | **全局唯一**（`uk_tag_name(tag_name, deleted)`），跨父级也不允许同名 | 标签没有层级概念，全局唯一才有意义（分类是**同级**唯一，因为分类有层级） |
| 12 | 标签停用后能否继续被选中 | **不能**：打标时校验，停用标签返回 `12005` | ⚠️ 借用了"分类已停用"的码 —— `12000~12999` 段位里**没有**"标签已停用"的专用码，而本步纪律是**不新增错误码**。自定义 message 把语义说清楚，比越界新增一个码更稳妥 |
| 13 | `report:export` 为何没有接口 | **有码无接口**（`report:export` 只有 ADMIN 有，但没有任何端点使用它） | 导出需要返回**文件流**，与"所有接口必须返回 `Result` 包装体"这条冻结约定**直接冲突**。需要专门的下载响应设计（`ResponseEntity<Resource>` + 例外约定），属结构级决策 → 本期不做，登记 |
| 14 | `category:audit` 为何没有接口 | **有码无接口**（分类审批流程未实现） | 新建分类时 `audit_status` **固定写 1（已生效）**。若置 0（待审批），新建的分类会永远停在待审批、**无法被文章选用**，功能是断的。⚠️ 这是**有意的取舍**，不是忘了 |

> ⚠️ **偏差 1~4 是同一类问题**：契约是"设计期"写的，库表是"运行期"的真相。
> 项目口径 = **库表 > 契约**（口头约定与契约冲突时以库表为准），这条在 `docs/接口分类与鉴权表.md` 有专段。
> **偏差 8~14 是 S24 新增的**：契约里没有的新域按"代码即规格"登记，两条"有码无接口"主动坦白。
