## 一、通用约定（所有接口共用，先看这一节）

### 1.1 统一返回体

所有接口返回 `Result<T>`，HTTP 状态码与业务码**同时**设置：

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | Integer | 业务码。成功固定 `200` |
| `message` | String | 提示信息。**成功的 message 固定为「操作成功」**，除非接口显式传了自定义文案 |
| `data` | T | 业务数据，可为 `null`（`Void` 接口即 `null`） |
| `timestamp` | Long | 服务端时间戳（epoch 毫秒） |

```json
{ "code": 200, "message": "操作成功", "data": null, "timestamp": 1780000000000 }
```

### 1.2 双层错误码（**最容易误判的一点**）

| 码段 | 含义 | HTTP 状态 |
|---|---|---|
| `100 ~ 599` | HTTP 语义码（400 参数错 / 401 未登录 / 403 无权限 / 404 / 500） | **同步设置**为对应 HTTP 状态 |
| `10xxx ~ 14xxx` | 业务码（文章、权限、认证等） | **保持 HTTP 200** |

> ⚠️ 因此**不能只断言 HTTP 200**：`11002`（状态非法）、`11003`（水平越权）、`11011`（已归档只读）
> 这些"业务失败"的 HTTP 都是 **200**，必须读 `body.code`。
> 这条在 S16 联调时就踩过（12 条越权与非法流转用例会全部"假通过"）。

文章域常用业务码：

| 码 | 含义 | 码 | 含义 |
|---|---|---|---|
| 11001 | 文章不存在 | 11009 | 版本不存在 |
| 11002 | 当前状态不允许该操作 | 11010 | 乐观锁冲突（并发） |
| 11003 | 只能操作自己创建的文章（水平越权） | 11011 | 已归档，只读 |
| 11004 | 不能审核自己创建的文章（自审） | 11013 | 只有草稿或已驳回可以删除 |
| 11007 | 排期时间非法 | 11014 | 驳回必须填写审核意见 |
| 13003 | 用户名或密码错误（认证域） | | |

### 1.3 认证方式：**Session（Cookie）**，不是 Bearer Token

- 登录成功后服务端写 Session，浏览器带 `JSESSIONID` Cookie 访问。
- 未登录访问受保护接口 → **HTTP 401**，由 `LoginInterceptor` 出（不是权限切面）。
- 已登录但缺权限码 → **HTTP 403**，由 `PermissionAspect`（AOP）出。
- 已登录、有权限但数据不属于自己 → **HTTP 200 + code 11003**，由 Service 层的归属校验出。

> ⚠️ 三级失败形态完全不同，排查时别混：**401 = 没登录 / 403 = 没权限 / 11003 = 不是你的数据**。

### 1.4 分页参数（继承 `PageQuery`）

| 参数 | 默认 | 约束 | 说明 |
|---|---|---|---|
| `page` | `1` | `< 1` 归一化为 `1`；超出总页数**不截断**，返回空 `records` | 页码 |
| `size` | `10` | `≤ 0` 归一化为 `10`；`> 100` **截断为 `100`** | 每页条数 |
| `sortField` | `null` | **白名单校验**，非白名单列返回 **HTTP 400** | 排序字段 |
| `sortOrder` | `desc` | 只接受 `asc` / `desc`，其它值按 `desc` 处理 | 排序方向 |

分页返回 `PageResult<T>`：`{ records, total, current, size, pages }`。

### 1.5 时间格式

- **请求**（query string 与 JSON body 一致）：`yyyy-MM-dd HH:mm:ss` / `yyyy-MM-dd HH:mm` / `yyyy-MM-dd` 三种写法均可。
- ⚠️ **刻意不接受 ISO 的 `T` 写法**（`2026-11-09T10:00:00`）—— 保持口径唯一，见 §七 的说明。
- **响应**：`yyyy-MM-dd HH:mm:ss`（由 `JacksonConfig` 统一序列化）。

## 二、文章域接口清单（16 个）

基础路径 `/api/v1/articles`，控制器 `com.lab.cms.controller.ArticleController`（500 行）。

| # | 方法 | 路径 | 功能 | 权限标识 | 请求参数 | 返回 | 备注 |
|---|---|---|---|---|---|---|---|
| A01 | GET | `/api/v1/articles` | 文章分页检索（列表页数据源） | `article:view` | query：`page`/`size`/`sortField`/`sortOrder` + `title`/`categoryId`/`status`/`authorId`/`beginTime`/`endTime`（均可选） | `PageResult<CmsArticleVO>` | 查询接口**不记操作日志**；出参**不含** `content`/`deleted`/`version`，含 `statusDesc`/`statusColor` |
| A02 | POST | `/api/v1/articles/draft` | 新建草稿 | `article:create` | body `CmsArticleSaveDTO` | `Long`（新文章 ID） | **幂等性：否**（连点两次得两篇，前端负责禁用按钮）；`@OperLog(saveParams=false)` 防正文撑爆日志表 |
| A03 | PUT | `/api/v1/articles/{id}/draft` | 编辑草稿（整体替换） | `article:update` | path `id` + body `CmsArticleSaveDTO` | `Void` | **幂等性：是**（PUT 语义）；id 只走路径参数，body 里**没有** id 字段 |
| A04 | POST | `/api/v1/articles/{id}/submit` | 提交初审（`DRAFT`/`REJECTED` → 待编辑初审） | `article:submit` | path `id` | `Void` | 重复提交第二次返回 `11002`（比静默成功更明确）；用"动作式 URL"而非 `PUT /{id}/status`，客户端无法直接指定目标状态 |
| A05 | POST | `/api/v1/articles/batch-submit` | 批量提交初审 | `article:submit` | body `BatchSubmitDTO{ids:List<Long>}` | `BatchSubmitResultVO{total,successCount,failCount,failList[{id,reason}]}` | ⚠️ **有失败仍返回 200**，失败明细在 `data.failList`；逐条独立事务，互不拖累 |
| A06 | POST | `/api/v1/articles/{id}/audit` | 审核（初审/终审同一入口） | `article:audit` | path `id` + body `ArticleAuditDTO{auditAction,auditOpinion}` | `Void` | `auditAction` 只接受 `1`(通过)/`2`(驳回)，其它值 **HTTP 400**；驳回不填意见 → `11014`；审自己的稿 → `11004` |
| A07 | GET | `/api/v1/articles/{id}` | 文章详情 | `article:view` | path `id` | `CmsArticleDetailVO`（= 列表 VO + `content` + `rejectReason` + `auditLogs`） | 查询接口不记日志 |
| A08 | GET | `/api/v1/articles/{id}/audit-logs` | 审核流水列表 | `article:view` | path `id` | `List<ArticleAuditLogVO>` | 仅"审核"动作写流水；提交/发布/撤回/下架/归档/回滚**都不写** |
| A09 | POST | `/api/v1/articles/{id}/publish` | 立即发布（`APPROVED`/`WITHDRAWN` → 已发布） | `article:publish` | path `id` | `Void` | 发布成功即清空 `schedule_time`（排期使命结束）；并发冲突返 `11010` |
| A10 | POST | `/api/v1/articles/{id}/schedule` | 排期发布（→ 定时发布中） | `article:publish` | path `id` + body `CmsArticlePublishDTO{scheduleTime}` | `Void` | `scheduleTime` 必须是**未来时间**，否则 `11007`；到点由定时任务自动发布 |
| A11 | POST | `/api/v1/articles/{id}/withdraw` | 撤回（已发布 → 已撤回） | `article:withdraw` | path `id` | `Void` | **要归属校验**（只能撤回自己的稿）；撤回**可逆**（可再发布） |
| A12 | POST | `/api/v1/articles/{id}/offline` | 下架（已发布 → 已下架） | `article:manage` | path `id` + body `CmsArticleOfflineDTO{reason}` | `Void` | 运营职能，**不做归属校验**；原因只落在 `@OperLog` 的 `request_param`（D-08：暂无回显接口） |
| A13 | POST | `/api/v1/articles/{id}/archive` | 归档（已撤回/已下架 → 已归档） | `article:manage` | path `id` | `Void` | 归档是**终态**，无任何出边；此后任何写操作 `11011` |
| A14 | DELETE | `/api/v1/articles/{id}` | 删除（逻辑删除） | `article:delete` | path `id` | `Void` | **只有 `DRAFT`/`REJECTED` 可删**（否则 `11013`）；**要归属校验**；**不级联**删除版本与流水；S20 补齐 |
| A15 | GET | `/api/v1/articles/{id}/versions` | 版本快照列表 | `article:view` | path `id` | `List<CmsArticleVersionVO>` | 按 `versionNo` **正序**；**不含正文**（只给标题快照）；`isCurrent` 仅作标记 |
| A16 | POST | `/api/v1/articles/{id}/rollback` | 回滚到指定版本 | `article:update` | path `id` + body `CmsArticleRollbackDTO{versionNo}` | `Void` | `versionNo` 必须是正整数（`0`/缺失 → HTTP 400）；回滚是**新建一版**（只增不减）；**要归属校验**；已发布态回滚 `11002`（须先撤回） |

### 2.1 文章域状态机（客户端必须知道的行为约定）

10 个状态：`0` 草稿 / `1` 待编辑初审 / `2` 待主编终审 / `3` 已通过 / `4` 已驳回 /
`5` 已发布 / `6` 定时发布中 / `7` 已撤回 / `8` 已下架 / `9` 已归档。

| 状态 | 允许的动作 | 说明 |
|---|---|---|
| `0` 草稿 | 编辑、提交初审、删除 | |
| `1` 待编辑初审 | 审核 | 编辑 / 主编都可用同一入口 |
| `2` 待主编终审 | 审核 | |
| `3` 已通过 | 立即发布、排期发布 | |
| `4` 已驳回 | 编辑、提交初审、删除 | 驳回理由在详情 `rejectReason` |
| `5` 已发布 | 撤回、下架 | 可再发布（撤回后） |
| `6` 定时发布中 | ——（无人工动作） | **只有定时任务能推进** |
| `7` 已撤回 | 立即发布、归档 | 撤回**可逆** |
| `8` 已下架 | 归档 | ⚠️ **无出边到发布** —— 下架不可逆（手册 F06/S14 写"可重新发布"，与实现不符，以代码为准） |
| `9` 已归档 | ——（终态） | 任何写操作 `11011` |

> 14 条合法迁移全部集中在 `com.lab.cms.common.ArticleStateMachine`，唯一入口 `transfer(status, action)`；
> 各 Service 方法不写 `if-else` 判状态，状态不对时由状态机统一抛 `11002`。

## 五、核对方式与结论（怎么证明这份清单是准的）

### 5.1 生成方式

```bash
# 扫描所有 Controller 的端点 + 权限注解 + 完整方法签名
"C:/.../python.exe" -c "... 见 docs/接口清单.md 的生成脚本说明 ..."
```

脚本逻辑：合并多行方法签名 → 匹配 `@(Get|Post|Put|Delete)Mapping` →
在其**紧随的几行**里取 `@RequirePermission` 与 `@OperLog` → 与类上的 `@RequestMapping` 拼出完整路径。

> ⚠️ **权限注解在 mapping 的下一行，不在上一行** —— 第一版脚本只往上找，
> 结果 16 个端点的 `perm` 全是 `-`。这是"用脚本核对"时最容易犯的错，记在这里。

### 5.2 数量对账

| 控制器 | 端点数 | 与代码行数核对 |
|---|---|---|
| `ArticleController` | **16** | 500 行 |
| `AuthController` | **3** | 70 行 |
| `HealthController` | **5** | 173 行 |
| `SystemController` | **4** | 134 行 |
| **合计** | **28** | —— |

## 六、与《接口契约》的偏差（**以库表/代码为准**，逐条登记）

| # | 契约 §1.3 写的 | 实际实现 | 原因 |
|---|---|---|---|
| 1 | 列表接口权限 `article:list` | `article:view` | 库表 `sys_permission` 里**没有** `article:list`。照契约写会让所有角色（含 admin）都被 403 |
| 2 | 编辑草稿权限 `article:edit` | `article:update` | 同上，库里没有 `article:edit` |
| 3 | 下架权限 `article:offline` | `article:manage` | 同上，库里没有 `article:offline` |
| 4 | 归档权限 `article:archive` | `article:manage` | 同上，库里没有 `article:archive` |
| 5 | 分页参数未明确非法排序字段的行为 | **HTTP 400**，提示里列出可选列 | 防 SQL 排序注入（实测 `id;drop table cms_article` → 400） |
| 6 | 时间参数格式未明确 | 只接受三种"空格/短横线"写法，**不接受 ISO 的 `T`** | 项目里曾同时存在两条互不相干的 String→时间转换链（`@RequestBody` 走 Jackson、query 走 Spring 默认），S19 统一成一条并刻意不收 `T` |
| 7 | 删除接口未说明可否级联 | **不级联**删除版本与审核流水 | 审计要求：留档优于连坐删除（S18 定的口径） |

> ⚠️ **偏差 1~4 是同一类问题**：契约是"设计期"写的，库表是"运行期"的真相。
> 项目口径 = **库表 > 契约**（口头约定与契约冲突时以库表为准），这条在 `docs/接口分类与鉴权表.md` 有专段。
