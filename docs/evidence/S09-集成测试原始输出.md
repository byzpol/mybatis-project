## 3. 三条最关键的原始证据（逐条说明它证明了什么）

### 3.1 `[S09] 保存草稿：id=85，快照 versionNo=1，remark=创建草稿，createBy=0`

证明三件事同时成立：

| 断言 | 证明什么 |
|---|---|
| 返回了 id（85） | `saveDraft` 返回新主键，而不是 null（S07 的空壳就是怕这个） |
| `快照 versionNo=1 / remark=创建草稿` | 新建草稿确实写了第 1 条版本快照，且说明文案正确 |
| **`createBy=0`** | 审计填充器的**硬指标**。`create_by` 列没有数据库默认值，填不上就是 null；测试环境没有 HTTP 会话，故按项目约定落到 `SYSTEM_USER_ID=0`。HTTP 链路上它是 `1`（见真机证据文档），两者形成对照 |

### 3.2 `[S09] 版本号序列：[1, 2, 3]（无重复，DISTINCT=3）`

证明版本取号是**按文章**而不是全局：
- 序列恰好 `[1,2,3]`；
- `COUNT(DISTINCT version_no) = COUNT(*) = 3`，无重复；
- 若 XML 漏写 `WHERE article_id = ?`，上一轮测试留下的快照会把起始号推到 4；
- 若 XML 漏写 `AND deleted = 0`，软删过快照的号会被算进去，同样会让断言失败。

### 3.3 唯一键冲突的异常链（**本轮纠正了一处错误判断**）

```
org.springframework.dao.DuplicateKeyException :
  Cause: java.sql.SQLIntegrityConstraintViolationException:
  Duplicate entry '95-1' for key 'cms_article_version.uk_article_version'
```

- 写 `isDuplicateKey` 时的先验判断是"本项目没有异常翻译，抛出来的会是
  `org.apache.ibatis.exceptions.PersistenceException`"——**这是错的**。
- 实测抛出来的就是 `org.springframework.dao.DuplicateKeyException`。
- 好在 `isDuplicateKey` 是按"沿 cause 链逐一识别三种形态"写的，所以**代码本来就对**；
  但注释里那句错话必须改掉（已改）。
- 这条证据的价值：**"推理框架行为"是这次唯一出错的地方，而"跑一次看它抛什么"纠正了它。**
  假设当时按错判断写成"只 catch `PersistenceException`"，重试逻辑就是一段永不执行的死代码，
  症状只会是"并发时偶发提交失败"，几乎无法复现。
