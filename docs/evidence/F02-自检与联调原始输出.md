（上面这一行是 `| head -c 300` 截断的结果，末尾的孤立 `.` 就是截断点。）

**关键观察**：拿到的是 **Tomcat 的 HTML 错误页**，不是后端的统一 JSON 404。这个"HTML 而不是 JSON"的现象直接指向"请求没进 DispatcherServlet"，而不是"业务代码报错"。

修复（`frontend/vite.config.js`）：

```js
'/api': {
  target: 'http://localhost:8080',
  changeOrigin: true,
  rewrite: (path) => `/cms-mis${path}`
}
```

## 4. 前端自检（临时脚本，验证完即删）

### 4.1 为什么需要它

见第 1 节：`request.js` / `article.js` 还没有调用方，`vite build` 不转译它们，构建成功不代表文件正确。
所以临时写 `frontend/f02-selftest.html` + `frontend/f02-selftest.js`，**显式 import 真实模块**并直接调用真实拦截器函数跑断言；验证完成后两个文件已删除（`git status` 可确认没有残留）。

两种验证手段都用了：

- **直接喂假响应给真实拦截器**：`request.interceptors.response.handlers[0].fulfilled({ data: {code:401,...}, config: {} })` —— 能精确构造"业务码 401 / HTTP 401 / 两者同时"这些真实请求很难造的组合。
- **真实 HTTP 往返**：经 vite proxy → Tomcat 打 `/health/page-echo` 拿真 401。

### 4.2 执行命令

```bash
# 起 dev server（在 frontend 下）
npx vite --port 5199 --strictPort

# 无头浏览器跑断言并导出 DOM
PROF="D:/mybatis-demo/project1/target/f02-check/p-$(date +%s)"
"/c/Program Files/Google/Chrome/Application/chrome.exe" \
  --headless=new --disable-gpu --no-sandbox --no-proxy-server \
  --user-data-dir="$PROF" --virtual-time-budget=20000 \
  --dump-dom "http://localhost:5199/f02-selftest.html?e2e=1" \
  > target/f02-check/dump-e2e.html
```

### 4.4 一处排查记录：`search="?redirect=/403"`

E2E 段最初挂在 `if (location.search.includes('e2e'))` 后面，结果**一直不执行且无异常**，看起来像代码没生效。

原因：跑在前面的 401 用例执行了 `router.replace({ path: '/login', query: { redirect: '/403' } })`，把地址改成了 `...f02-selftest.html?redirect=/403`，原来的 `?e2e=1` 被覆盖。

把 `location.search` 打进输出即定位（`search="?redirect=/403"`）——**顺带证明 `redirect` 参数确实写进了 URL**。

### 4.5 一个曾被验证的方案：`ElMessage.error` 打桩的兜底

数"弹了几次提示"的做法是临时替换 `ElMessage.error`。因为 element-plus 导出对象属性是否可写没有保证，脚本加了兜底：打桩后校验 `ElMessage.error !== orig`，失败则退回 `document.querySelectorAll('.el-message').length` 计数。

实测打桩成功（输出里的 `calls=[...]` 就是打桩记录）。
