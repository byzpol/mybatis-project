## 三、配置数据库连接（`db.properties`）

⚠️ **文件名是 `db.properties`，不是指导书里写的 `jdbc.properties`**（两个都已被 `.gitignore` 排除，
但工程实际读的是前者）。

### 3.1 复制模板

```bash
# 【bash】在工程根目录
cp src/main/resources/db.properties.example src/main/resources/db.properties
# ⚠️ db.properties 已在 .gitignore 里，永远不要 commit、不要截图到报告
```

### 3.2 只改一行：口令

打开 `src/main/resources/db.properties`，把：

```properties
jdbc.password=your_password_here
```

改成你本机 MySQL 的真实口令。**其余参数不要动**，尤其是连接串里的四个参数：

| 参数 | 为什么不能删 |
|---|---|
| `characterEncoding=utf8` | 中文不乱码（UTF-8 全链路） |
| `serverTimezone=Asia/Shanghai` | MySQL 8+ 必须指定时区，否则报时区错误 / 时间差 8 小时 |
| `allowPublicKeyRetrieval=true` | ⚠️ **删了会在 MySQL 重启后炸**（见下） |
| `useSSL=false` | 本地开发不走 SSL，避免证书警告 |

> ⚠️ **`allowPublicKeyRetrieval=true` 是本项目 S08 实测踩到的坑**：
> root 用户用的是 `caching_sha2_password` 认证，服务端有密码缓存，缓存命中走快速认证；
> **MySQL 一旦重启，缓存清空**，首次连接要走完整认证，在 `useSSL=false` 下必须向服务端索取 RSA 公钥。
> 少了这个参数会报 `Public Key Retrieval is not allowed`，**连接池直接起不来，所有数据库操作全挂**。
> 症状迷惑点：不重启 MySQL 就一直正常，**重启后才炸** —— 很容易误判成"代码改坏了"。


> 它相对于**Tomcat 进程的工作目录**，与 `CATALINA_HOME` 无关。
> 不在工程根启动 → 日志落在别处，"按文档去 `<Tomcat>/logs/` 找 cms.log"会**一条都找不到**。

**怎么确认启动成功**（三个判据，缺一不可）：


## 八、常见启动问题排查（现象 → 原因 → 解决）

> 这张表是按"本项目实际踩过的坑"整理的，不是通用模板。

### 8.1 `ClassNotFoundException: javax.servlet.*`（或 `jakarta.servlet.*`）

| 项 | 内容 |
|---|---|
| **现象** | 启动时抛 `ClassNotFoundException` / `NoClassDefFoundError`，类名里带 `javax.servlet` 或 `jakarta.servlet` |
| **原因** | **Tomcat 版本选错**。Spring 5.3.x / Servlet 4.0 用 `javax.servlet`；**Tomcat 10+ 换成了 `jakarta.servlet`**，命名空间不兼容 |
| **解决** | 换回 **Tomcat 9.x**。本项目实测版本：`Apache Tomcat/9.0.122` |

### 8.2 Bean 注入失败：`NoSuchBeanDefinitionException` / `Field xxx required a bean`

| 项 | 内容 |
|---|---|
| **现象** | 启动报找不到某个 Bean，或 `@Autowired` 的字段注入失败 |
| **原因** | ① 组件没被扫到（不在 `com.lab.cms` 包下，或漏了 `@Service`/`@Component`/`@Repository`）；② **`@Transactional` 的同类自调用**（不报错但事务不生效，见 8.5）；③ 依赖没打进 war |
| **排查** | 看 `cms.log` 启动段的完整堆栈，找到**第一个** `NoSuchBeanDefinitionException`；确认该类的包路径在 `<context:component-scan base-package="com.lab.cms"/>` 范围内 |
| **解决** | 补注解 / 移到正确包下；依赖缺失则检查 `pom.xml` 与 war 的 `WEB-INF/lib` |

### 8.3 静态资源 404 / 页面白屏

| 项 | 内容 |
|---|---|
| **现象** | 访问 `/cms-mis/` 返回 404，或返回了 HTML 但页面白屏、加载不到 `/assets/xxx.js` |
| **原因** | ⚠️ **打 war 之前没先 `npm run build`** —— `src/main/webapp/` 是 gitignore 的前端产物，克隆仓库后它**是空的** |
| **排查** | `unzip -l target/cms-mis.war \| grep index.html` —— 没有就是没 build 前端 |
| **解决** | 按 §5.1 先 build 前端，**再** `mvn package`（顺序不能颠倒） |

### 8.4 直接访问子路由 / 刷新页面 **404**（本项目 S20 修掉的严重缺陷 D-12）

| 项 | 内容 |
|---|---|
| **现象** | `http://localhost:8080/cms-mis/articles/list` 直接访问或按 F5 → **404**（统一 JSON 404）。只有先访问 `/cms-mis/` 再由前端路由跳转才正常 |
| **原因** | 前端用 `createWebHistory`（真路径），但后端**没有把未知的非 API 路径 forward 到 `index.html` 的配置**，Spring MVC 按"没有这个 handler"处理 → 落到统一 JSON 404 |
| **解决** | `SpringMvcConfig#addViewControllers` 里把前端**一级路由逐条白名单** forward 到 `index.html`（`/login`、`/403`、`/profile`、`/articles/**`、`/categories`、`/tags`、`/users`、`/roles`、`/logs/**`、`/reports`）<br/>⚠️ **不要用 `/**` 一把兜住** —— 那会把统一 JSON 404 冲掉，写错的接口路径会返回 200 的 HTML<br/>⚠️ 必须是 **forward 而不是 redirect**（redirect 会改地址栏、丢原始路径，再刷新又回到 `/index.html`） |
| **维护约束** | 前端**每加一个一级路由，必须同步在这里加一行**（已写进该方法的 Javadoc） |

### 8.5 事务不回滚（**最隐蔽的一类，不报错**）

| 项 | 内容 |
|---|---|
| **现象** | 业务报"失败"，但库里数据**半改**了；或"失败日志"根本没写进表 |
| **原因** | ① **`@Transactional` 同类自调用不生效**（走不到 Spring 代理）；② 异常类型不在回滚范围（默认只回滚 `RuntimeException`）；③ 方法不是 `public`；④ 调用方本身在同一个事务里、异常被吞掉 |
| **排查** | 打开 `cms.log` 搜 `Rolling back` / `Preparing:` —— **"静默失效"的唯一判据就是日志里的实际 SQL**，不要只看代码 |
| **解决** | ① 需要独立事务的逻辑抽到**独立 Bean**，**经外部接口调用**（本项目 `LoginLogService` + `REQUIRES_NEW` 即为此，见 `docs/结题报告.md` §5.7 的 D-10）；② `@Transactional(rollbackFor = Exception.class)` 显式声明；③ 异常必须 **rethrow**，不能 catch 后吞掉 |
| **本项目实测的确定性失败点** | 用 600 字审核意见触发 `opinion VARCHAR(500)` 的 `1406` → 状态回滚、审核流水**不留半条**（`docs/回归测试报告.md` §2.6） |

### 8.6 中文乱码

| 项 | 内容 |
|---|---|
| **现象** | 页面或接口返回的中文变成 `????`；库里数据是乱码 |
| **原因** | 全链路四层里任一层不是 UTF-8：① MySQL 库/表/连接；② JDBC 连接串；③ Servlet 请求/响应；④ 编译源文件编码 |
| **解决（本项目已全部配好，逐层核对）** | ① 建库脚本用 `utf8mb4`；② 连接串有 `characterEncoding=utf8`；③ `ServletContainersInitConfig` 注册了 `CharacterEncodingFilter`（UTF-8）；④ `pom.xml` 的 `project.build.sourceEncoding=UTF-8` |
| **特别提醒** | 用 `curl` 抓接口时，响应 `Content-Type` 可能不带 `charset`，终端按 ISO-8859-1 解码也会显示乱码 —— **那是终端的问题，不是服务的问题**。用浏览器或 `curl ... \| python -c "import sys;print(sys.stdin.buffer.read().decode('utf-8'))"` 判定 |

### 8.7 时间差 8 小时

| 项 | 内容 |
|---|---|
| **现象** | 页面上显示的创建/发布时间比实际早或晚 8 小时 |
| **原因** | JDBC 连接串缺 `serverTimezone=Asia/Shanghai`，JDBC 驱动按 UTC 解释 `DATETIME` |
| **解决** | 连接串补上该参数（模板里已有，删不得）；项目里所有时间字段统一用 `LocalDateTime`（无时区语义），不做时区换算 |

### 8.8 `Public Key Retrieval is not allowed`（**只在 MySQL 重启后出现**）

| 项 | 内容 |
|---|---|
| **现象** | 平时好好的，**MySQL 重启后**连接池初始化失败，报 `Public Key Retrieval is not allowed` |
| **原因** | `caching_sha2_password` 的服务端密码缓存在重启后清空，首次连接要走完整认证，在 `useSSL=false` 下必须索取 RSA 公钥 |
| **解决** | 连接串加 `allowPublicKeyRetrieval=true`（模板里已有）。生产环境应改用 `useSSL=true&requireSSL=true` |

### 8.9 日志文件找不到

| 项 | 内容 |
|---|---|
| **现象** | 按文档去 `<Tomcat>/logs/` 找 `cms.log`，**一条都找不到** |
| **原因** | `logback.xml` 里 `LOG_PATH=./logs` 是**相对路径**，相对于**Tomcat 进程的工作目录** |
| **解决** | 启动前 `cd` 到工程根（§6.4 的命令就是这么写的），日志会落在 `project1/logs/` |

### 8.10 端口 8080 被占用

| 项 | 内容 |
|---|---|
| **现象** | 启动报 `Address already in use: bind` |
| **排查/解决** | `netstat -ano \| grep ":8080" \| grep LISTENING` 取 PID → `taskkill //F //PID <PID>`；或改 `conf/server.xml` 的 Connector 端口（改了前端 `vite.config.js` 的 proxy 目标也要跟着改） |
