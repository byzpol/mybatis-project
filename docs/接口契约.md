# 接口契约说明书（契约主干 · 冻结版）

> 项目：企业级 CMS 内容管理系统（课程项目）
> 版本：**V1.0（冻结日 2026-10-16，tag `trunk-v1.0`）**
> 编制：成员A（技术负责人）
> 效力：**本文件冻结后，"主干"部分任何人不得改签名；"入户线"部分各负责人可自行扩充，但必须遵守本文件全部约定**
> 用途：① 前后端并行开发的对齐依据　② ApiFox 用例集的编写依据　③ 代码评审的判定标准

## 〇、为什么需要这份文件

四个人 + 四个业务域 + 一个前端，如果每个人各自定 URL、各自定返回体、各自定错误码，那么：

- 前端要为四个模块写四套 axios 处理逻辑
- 联调时"这个接口返回的是数组还是对象"要一个个问
- 出错了不知道 `code=3001` 是谁定义的

所以本项目采用 **"契约先行 + 主干冻结"**：

> **主干**：`/api/v1` 前缀、`Result<T>` 返回体、`PageQuery`/`PageResult` 分页体、状态码分段、`@RequirePermission`、`@OperLog` —— **由成员A 一次建好，冻结后只加不改**。
> **入户线**：各业务域自己的 `entity → mapper → service → impl → dto/vo → controller`，**只需 import 主干，不许复制主干代码**。

这份文件就是主干的文字契约。

## 一、URL 命名规范

### 1.1 五条硬规则

| # | 规则 | 正例 | 反例 |
|---|---|---|---|
| 1 | 统一前缀 `/api/v1/` | `/api/v1/articles` | `/article`、`/api/article` |
| 2 | 资源用**复数名词**，全小写，连字符分隔 | `/api/v1/audit-logs` | `/api/v1/getArticleList`、`/api/v1/AuditLog` |
| 3 | 路径层级 ≤ 3（不含前缀） | `/api/v1/articles/{id}/audit` | `/api/v1/admin/articles/{id}/audit/do/pass` |
| 4 | **状态变更用子资源 + POST**，不用 PUT 表达"动作" | `POST /api/v1/articles/{id}/submit` | `PUT /api/v1/articles/{id}/status` |
| 5 | 查询参数一律小驼峰 | `?page=1&size=10&sortField=createTime` | `?Page=1&sort_field=create_time` |

- **`{id}` 一律为路径变量**，用 `@PathVariable` 接。
- **批量操作用 `batch-` 前缀的子资源**：`POST /api/v1/articles/batch-submit`，请求体带 `ids` 数组。

### 1.2 为什么状态变更不用 PUT

`PUT /articles/{id}` 的语义是"整体替换这个资源"，而"提交初审"是**领域动作**，不是资源替换。用 `POST /articles/{id}/submit` 有三个好处：

1. URL 自解释 —— 看日志就知道发生了什么动作
2. 每个动作可独立做权限控制（`article:submit` / `article:audit` / `article:publish`）
3. 便于在 AOP 里统一记操作日志（`@OperLog` 拿得到动作名）

### 1.3 文章域完整接口清单（15 个）

| # | 方法 | URL | 功能 | 权限码 | 幂等 | 日志 |
|---|---|---|---|---|---|---|
| 1 | GET | `/api/v1/articles` | 分页检索（含状态/分类/关键词筛选） | `article:list` | 是 | 否 |
| 2 | GET | `/api/v1/articles/{id}` | 文章详情 | `article:view` | 是 | 否 |

| 5 | DELETE | `/api/v1/articles/{id}` | 删除（仅草稿/驳回态） | `article:delete` | 是 | 是 |
| 6 | POST | `/api/v1/articles/{id}/submit` | 提交初审 | `article:submit` | 否 | 是 |
| 7 | POST | `/api/v1/articles/batch-submit` | 批量提交初审 | `article:submit` | 否 | 是 |

## 二、统一返回体

### 2.1 `Result<T>`

```java
package com.lab.cms.common.result;

import com.lab.cms.common.exception.ErrorCode;
import lombok.Data;

import java.io.Serializable;

/**
 * 统一响应体。
 * 全项目所有 Controller 的返回值都必须是 Result 或 PageResult，
 * 不允许直接返回实体、List、Map。
 *
 * @param <T> 业务数据类型
 */
@Data
public class Result<T> implements Serializable {

    private static final long serialVersionUID = 1L;

    /** 状态码：200 表示成功，其余见 ErrorCode */
    private Integer code;

    /** 提示信息：成功固定 "操作成功"，失败为可读的中文原因 */
    private String message;

    /** 业务数据：失败时为 null */
    private T data;

    /** 服务器时间戳（毫秒），便于前端排查时序问题 */
    private Long timestamp;

    private Result(Integer code, String message, T data) {
        this.code = code;
        this.message = message;
        this.data = data;
        this.timestamp = System.currentTimeMillis();
    }

    // ---------- 成功 ----------

    public static <T> Result<T> success() {
        return new Result<>(200, "操作成功", null);
    }

    public static <T> Result<T> success(T data) {
        return new Result<>(200, "操作成功", data);
    }

    public static <T> Result<T> success(String message, T data) {
        return new Result<>(200, message, data);
    }

    // ---------- 失败 ----------

    public static <T> Result<T> fail(Integer code, String message) {
        return new Result<>(code, message, null);
    }

    public static <T> Result<T> fail(ErrorCode errorCode) {
        return new Result<>(errorCode.getCode(), errorCode.getMessage(), null);
    }

    /** 业务异常：用错误码 + 自定义说明（如"文章当前状态不允许提交初审"） */
    public static <T> Result<T> fail(ErrorCode errorCode, String message) {
        return new Result<>(errorCode.getCode(), message, null);
    }
}
```

**JSON 形态**

```json
// 成功（有数据）
{ "code": 200, "message": "操作成功", "data": { "id": 1, "title": "..." }, "timestamp": 1759820400000 }

// 成功（无数据，如删除）
{ "code": 200, "message": "操作成功", "data": null, "timestamp": 1759820400000 }

// 失败（业务规则拦截）
{ "code": 11102, "message": "文章当前状态为「已发布」，不允许提交初审", "data": null, "timestamp": 1759820400123 }

// 失败（参数校验，ValidationError 由全局异常处理器组装）
{ "code": 400, "message": "参数校验失败：title 不能为空；categoryId 必须为正整数", "data": null, "timestamp": 1759820400123 }
```

### 2.2 `PageResult<T>`

```java
package com.lab.cms.common.result;

import lombok.Data;

import java.io.Serializable;
import java.util.Collections;
import java.util.List;

/**
 * 统一分页响应体。
 * 前端 PageTable 组件直接消费这五个字段，不允许改字段名。
 *
 * @param <T> 记录类型
 */
@Data
public class PageResult<T> implements Serializable {

    private static final long serialVersionUID = 1L;

    /** 当前页记录 */
    private List<T> records;

    /** 总记录数 */
    private Long total;

    /** 当前页码（从 1 开始） */
    private Long current;

    /** 每页条数 */
    private Long size;

    /** 总页数（由 total/size 向上取整得出） */
    private Long pages;

    public PageResult() {
    }

    public PageResult(List<T> records, Long total, Long current, Long size) {
        this.records = records == null ? Collections.emptyList() : records;
        this.total = total == null ? 0L : total;
        this.current = current == null ? 1L : current;
        this.size = size == null ? 10L : size;
        this.pages = this.size == 0 ? 0L : (this.total + this.size - 1) / this.size;
    }

    /** 从 MyBatis-Plus 的 IPage 转换 */
    public static <T> PageResult<T> of(com.baomidou.mybatisplus.core.metadata.IPage<T> page) {
        return new PageResult<>(page.getRecords(), page.getTotal(), page.getCurrent(), page.getSize());
    }

    /** 空分页 */
    public static <T> PageResult<T> empty(Long current, Long size) {
        return new PageResult<>(Collections.emptyList(), 0L, current, size);
    }
}
```

> **为什么不直接返回 MP 的 `IPage`**：`IPage` 序列化出来字段有 `records/total/size/current/pages/orders/optimizeCountSql/searchCount/...` 十几个字段，前端要过滤。固定成五个字段，前端契约就锁死了。

### 2.3 `PageQuery`（分页入参基类）

```java
package com.lab.cms.common.result;

import lombok.Data;

import java.io.Serializable;

/**
 * 统一分页入参基类。
 * 各业务域的查询 DTO 继承本类，如 ArticleQueryDTO extends PageQuery。
 * 字段名固定为 page/size/sortField/sortOrder，前端统一传。
 */
@Data
public class PageQuery implements Serializable {

    private static final long serialVersionUID = 1L;

    /** 每页最大条数（防前端传 size=999999 拖垮数据库） */
    public static final int MAX_SIZE = 100;
    /** 默认每页条数 */
    public static final int DEFAULT_SIZE = 10;

    /** 页码，从 1 开始 */
    private Integer page = 1;

    /** 每页条数，默认 10，上限 100 */
    private Integer size = DEFAULT_SIZE;

    /** 排序字段（白名单校验，见下） */
    private String sortField;

    /** 排序方向：asc / desc（不区分大小写），默认 desc */
    private String sortOrder = "desc";

    /**
     * 归一化：修正非法 page/size，防止 SQL 注入式的排序字段。
     * 在每个 Service 的分页查询开头调用一次。
     */
    public void normalize() {
        if (page == null || page < 1) {
            page = 1;
        }
        if (size == null || size < 1) {
            size = DEFAULT_SIZE;
        }
        if (size > MAX_SIZE) {
            size = MAX_SIZE;
        }
        if (sortOrder == null || (!"asc".equalsIgnoreCase(sortOrder) && !"desc".equalsIgnoreCase(sortOrder))) {
            sortOrder = "desc";
        }
        // sortField 不在这里兜底，必须由各域显式白名单校验，见 3.4 节
    }

    public Integer getPage() {
        return page;
    }

    public Integer getSize() {
        return size;
    }

    public String getSortField() {
        return sortField;
    }

    public String getSortOrder() {
        return sortOrder;
    }
}
```

**排序字段白名单（必须显式校验）**

```java
// 写在 ArticleServiceImpl 里，不允许直接拼接到 SQL
private static final Set<String> SORTABLE = Set.of(
        "createTime", "updateTime", "publishTime", "viewCount", "title"
);

private void checkSortField(PageQuery query) {
    if (query.getSortField() != null && !SORTABLE.contains(query.getSortField())) {
        throw new BusinessException(ErrorCode.PARAM_ERROR, "不支持的排序字段：" + query.getSortField());
    }
}
```

> ⚠️ **这是 SQL 注入的高危点**：`ORDER BY ${sortField}` 必然是字符串拼接（MyBatis 的 `#{}` 不能用于列名）。因此排序字段**必须**走白名单，绝不能信任前端。

### 2.4 MyBatis-Plus 分页拦截器配置（主干提供）

```java
package com.lab.cms.config;

import com.baomidou.mybatisplus.annotation.DbType;
import com.baomidou.mybatisplus.extension.plugins.MybatisPlusInterceptor;
import com.baomidou.mybatisplus.extension.plugins.inner.OptimisticLockerInnerInterceptor;
import com.baomidou.mybatisplus.extension.plugins.inner.PaginationInnerInterceptor;
import com.baomidou.mybatisplus.extension.plugins.inner.BlockAttackInnerInterceptor;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class MybatisPlusConfig {

    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();

        // 1. 分页插件（注意：DbType 必须是 MYSQL）
        PaginationInnerInterceptor pagination = new PaginationInnerInterceptor(DbType.MYSQL);
        pagination.setMaxLimit(100L);   // 与 PageQuery.MAX_SIZE 保持一致
        pagination.setOverflow(false);  // 页码超范围时返回空列表，不回到第一页
        interceptor.addInnerInterceptor(pagination);

        // 2. 乐观锁插件（cms_article.version / cms_article_version 用到）
        interceptor.addInnerInterceptor(new OptimisticLockerInnerInterceptor());

        // 3. 防全表更新删除插件（拦 update/delete 不带 where 的误操作）
        interceptor.addInnerInterceptor(new BlockAttackInnerInterceptor());

        return interceptor;
    }
}
```

> **插件顺序有讲究**：分页插件必须放在最后加（MP 官方要求"多个插件时，分页插件最后添加"，因为分页会改写 SQL，若前面插件改了 SQL 会导致分页算错）。上面的写法实际把分页加了第一个 —— **这是错的**，正确顺序见下：

```java
    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        // 先加非分页插件
        interceptor.addInnerInterceptor(new OptimisticLockerInnerInterceptor());
        interceptor.addInnerInterceptor(new BlockAttackInnerInterceptor());
        // 分页插件必须最后加
        PaginationInnerInterceptor pagination = new PaginationInnerInterceptor(DbType.MYSQL);
        pagination.setMaxLimit(100L);
        pagination.setOverflow(false);
        interceptor.addInnerInterceptor(pagination);
        return interceptor;
    }
```

## 三、错误码分段表

### 3.1 分段规则

| 段位 | 归属 | 使用人 |
|---|---|---|
| `200` | 成功 | — |
| `400 / 401 / 403 / 404 / 405 / 409 / 415 / 500` | HTTP 语义错误码（与 HTTP 状态码一致） | 主干统一抛 |
| `10000 ~ 10999` | **通用业务码** | 主干（成员A） |
| `11000 ~ 11999` | **文章域** | 成员A |
| `12000 ~ 12999` | **分类与标签域** | 成员B |
| `13000 ~ 13999` | **用户权限与授权审批域** | 成员C |
| `14000 ~ 14999` | **日志与统计域** | 成员D |

**段位分配纪律**：每人只在自己段位内新增码，**不得占用他人段位**。新增码必须同步到本文件（在 §3.3 之后的各域表中追加）。

### 3.3 与 HTTP 状态码的映射关系

> **⚠️ 本节于 2026-10-16（S08 主干自测）修正过一次。**
> 原表述是"统一走 HTTP 200 + 业务码，只有 401 例外"，
> 但 S05 实现 `GlobalExceptionHandler` 时采用了**HTTP 状态码与业务码同时设置**的方案
> （理由见该类注释：HTTP 恒 200 会让 axios 拦截器、网关监控、缓存重试语义全部失准）。
> S08 的 13 项端到端自测把实际行为逐条测了出来，本节据此改写为**实际行为**。
> 各负责人写前端拦截器时请以本节为准。

**规则一句话**：`GlobalExceptionHandler` 会把"落在 HTTP 合法区间（100~599）"的业务码**同步**写到 HTTP 状态码上；
业务码若在 10xxx~14xxx 段（不在该区间），HTTP 状态码保持 200，错误细节由响应体 `code` 承载。

| 场景 | HTTP 状态码 | 响应体 `code` | 由谁产生 |
|---|---|---|---|
| 正常 | 200 | 200 | — |
| 业务失败（状态机拦截、不是本人文章等） | **200** | 10xxx ~ 14xxx | Service 抛 `BusinessException` |
| 未登录 / 会话过期 | **401** | 401 或 10001 | `LoginInterceptor`；或 `BusinessException(UNAUTHORIZED)` |
| 无权限（垂直越权） | **403** | 403 | `PermissionAspect` 抛 `BusinessException(FORBIDDEN)` |
| 无权限（水平越权） | **200** | 10007 / 11003 | Service 层所有权校验 |
| 参数校验失败（`@Valid` / 缺必填参 / 类型不匹配 / JSON 格式错） | **400** | 400 | `GlobalExceptionHandler` 各分支 |
| 路径不存在 | **404** | 404 | `GlobalExceptionHandler#handleNoHandlerFound` |
| 请求方法不支持 | **405** | 405 | `GlobalExceptionHandler` |
| 请求媒体类型不支持 | **415** | 415 | `GlobalExceptionHandler` |
| 未捕获的系统异常 | **500** | 500 | `GlobalExceptionHandler` 兜底（日志 ERROR + 堆栈，响应体**不含**堆栈） |

> **为什么业务失败用 HTTP 200 而协议级错误用真实状态码**：
> "文章状态不允许提交"是**业务结果**（请求本身完全合法），用 200 + 业务码表达最贴切；
> 而 404/405/415 是**协议级错误**（路径不存在、方法不匹配、格式不对），
> 本身就是 HTTP 语义，用标准状态码更利于工具识别与排查。
> 前端的最佳实践是**两条路都走**：拦截器按 HTTP 状态码做统一兜底（401 跳登录、5xx 报错），
> 业务提示则读响应体的 `code` / `message`。

> ⚠️ **404 已统一为 Result 结构**（S08 修复）。此前访问不存在的路径会返回 **Tomcat 的 HTML 错误页**，
> 原因是 `DispatcherServlet` 的 `throwExceptionIfNoHandlerFound` 默认为 `false`，
> 导致 `GlobalExceptionHandler` 里的 `handleNoHandlerFound` 成了死代码。
> 已在 `ServletContainersInitConfig#createDispatcherServlet` 中开启。
> 因此**所有** 404（包括 B/C/D 各域的路径）现在都返回 `{"code":404,"message":"接口不存在：..."}`。

### 4.1 `@RequirePermission`（垂直越权防护）

```java
package com.lab.cms.annotation;

import java.lang.annotation.*;

/**
 * 功能级权限校验注解。
 * 加在 Controller 方法或类上，由 PermissionAspect 通过 AOP 校验当前登录用户的权限码集合。
 * 校验的是"能不能用这个功能"，与"能不能看这条数据"（水平越权）是两回事，
 * 后者必须在 Service 层单独用 checkOwnership 校验。
 */
@Target({ElementType.METHOD, ElementType.TYPE})
@Retention(RetentionPolicy.RUNTIME)
@Documented
public @interface RequirePermission {

    /** 权限码，格式 "资源:动作"，如 "article:audit"。多个时是 AND 关系。 */
    String[] value();

    /** 多个权限码之间的关系，默认 AND */
    Logical logical() default Logical.AND;

    enum Logical {
        AND, OR
    }
}
```

**用法**

```java
@RestController
@RequestMapping("/api/v1/articles")
@RequiredArgsConstructor

    private final ArticleService articleService;

    @PostMapping("/{id}/audit")
    @RequirePermission("article:audit")
    @OperLog(module = "文章管理", type = OperType.AUDIT, desc = "审核文章")
    public Result<Void> audit(@PathVariable Long id,
                              @RequestBody @Valid ArticleAuditDTO dto) {
        articleService.audit(id, dto);
        return Result.success();
    }

    @PostMapping("/batch-submit")
    @RequirePermission(value = {"article:submit", "article:edit"}, logical = RequirePermission.Logical.OR)
    public Result<Integer> batchSubmit(@RequestBody @Valid BatchSubmitDTO dto) {
        return Result.success(articleService.batchSubmit(dto.getIds()));
    }
}
```

```java
package com.lab.cms.common.constant;

import lombok.Data;

import java.io.Serializable;
import java.util.Set;

/**
 * 登录用户会话对象。
 * 由 AuthServiceImpl 登录成功后放入 HttpSession（key = SessionConstant.LOGIN_USER）。
 * 全项目只认这一个用户模型，不允许各自建 UserContext。

@Data
public class LoginUser implements Serializable {

    private static final long serialVersionUID = 1L;

    private Long userId;
    private String username;
    private String nickname;
    private String avatar;

    /** 角色码集合，如 ["ROLE_AUTHOR"] */
    private Set<String> roles;

    /** 是否拥有全部权限（超级管理员） */
    private Boolean superAdmin;

    /** 判断是否拥有某权限 */
    public boolean hasPermission(String code) {
        if (Boolean.TRUE.equals(superAdmin)) {
            return true;
        }
        return permissions != null && permissions.contains(code);
    }

    /** 判断是否拥有任一权限 */
    public boolean hasAnyPermission(String... codes) {
        if (Boolean.TRUE.equals(superAdmin)) {
            return true;
        }
        if (permissions == null) {
            return false;
        }
        for (String code : codes) {
            if (permissions.contains(code)) {
                return true;
            }
        }
        return false;
    }

    /** 判断是否拥有某角色 */
    public boolean hasRole(String roleCode) {
        return roles != null && roles.contains(roleCode);
    }
}
```

## 五、DTO / VO 约定

### 5.1 三类对象分工（不允许混用）

| 类型 | 后缀 | 用途 | 位置 | 举例 |
|---|---|---|---|---|
| **Entity** | 无后缀 | 与数据库表一一对应 | `entity` | `Article` |
| **DTO** | `DTO` | 接收入参（Controller 入参） | `dto` | `ArticleCreateDTO`、`ArticleQueryDTO` |
| **VO** | `VO` | 返回出参（Controller 出参） | `vo` | `ArticleVO`、`ArticleDetailVO` |

**四条纪律**

1. **Entity 绝不直接作为 Controller 入参或出参** —— 会暴露 `deleted`、`createBy` 等内部字段，且 Entity 加了字段前端就被动受影响。
2. **DTO 必须带校验注解** —— 每个 `@NotNull`/`@NotBlank`/`@Size` 都对应一条业务约束。
3. **VO 只包含前端需要的字段** —— 不需要的字段不要给（如不返回 `deleted`、不返回密码）。
4. **转换不引第三方工具**（MapStruct 需额外配置）—— Entity/DTO/VO 之间的转换显式写 `convert` 方法放在 `converter` 或 Service 内私有方法。

```java
        this.description = description;

    }

    public static ArticleStatus of(Integer code) {
        if (code == null) {
            return null;
        }
        return Arrays.stream(values())
                .filter(s -> s.code.equals(code))
                .findFirst()
                .orElseThrow(() -> new IllegalArgumentException("未知文章状态：" + code));
    }

    /** 是否为终态（终态不允许任何动作） */
    public boolean isFinal() {
        return this == ARCHIVED;
    }
}
```

### 6.3 状态机（主干提供的 `ArticleStateMachine`）

**这是全项目最重要的一个类**。所有状态流转必须走它，禁止在 Service 里散落 `if (status == 1) { ... }` 这类判断。

```java
package com.lab.cms.common;

import com.lab.cms.common.enums.ArticleAction;
import com.lab.cms.common.enums.ArticleStatus;
import com.lab.cms.common.exception.BusinessException;
import com.lab.cms.common.exception.ErrorCode;

import java.util.Collections;
import java.util.HashMap;
import java.util.Map;
import java.util.Set;

/**
 * 文章状态机。
 * 14 条合法迁移集中登记在此，是唯一的真相来源（Single Source of Truth）。
 * <p>
 * 禁止在业务代码里写 if (status == DRAFT) 之类的散落判断，
 * 一律调用 {@link #transfer} 或 {@link #canTransfer}。
 */
public final class ArticleStateMachine {

    private ArticleStateMachine() {
    }

    /** 迁移表：key = "当前状态枚举名:动作枚举名"，value = 目标状态 */
    private static final Map<String, ArticleStatus> TRANSITIONS;

    static {
        Map<String, ArticleStatus> map = new HashMap<>(32);

        // 1. 草稿 + 提交 → 待编辑初审
        map.put(key(ArticleStatus.DRAFT, ArticleAction.SUBMIT), ArticleStatus.PENDING_EDITOR);
        // 2. 已驳回 + 提交 → 待编辑初审（驳回后可以改完再交）
        map.put(key(ArticleStatus.REJECTED, ArticleAction.SUBMIT), ArticleStatus.PENDING_EDITOR);

        // 3. 待编辑初审 + 通过 → 待主编终审
        map.put(key(ArticleStatus.PENDING_EDITOR, ArticleAction.AUDIT_PASS), ArticleStatus.PENDING_CHIEF);
        // 4. 待编辑初审 + 驳回 → 已驳回
        map.put(key(ArticleStatus.PENDING_EDITOR, ArticleAction.AUDIT_REJECT), ArticleStatus.REJECTED);

        // 5. 待主编终审 + 通过 → 审核通过
        map.put(key(ArticleStatus.PENDING_CHIEF, ArticleAction.AUDIT_PASS), ArticleStatus.APPROVED);
        // 6. 待主编终审 + 驳回 → 已驳回
        map.put(key(ArticleStatus.PENDING_CHIEF, ArticleAction.AUDIT_REJECT), ArticleStatus.REJECTED);

        // 7. 审核通过 + 立即发布 → 已发布
        map.put(key(ArticleStatus.APPROVED, ArticleAction.PUBLISH_NOW), ArticleStatus.PUBLISHED);
        // 8. 审核通过 + 排期发布 → 定时发布中
        map.put(key(ArticleStatus.APPROVED, ArticleAction.PUBLISH_SCHEDULE), ArticleStatus.SCHEDULED);

        // 9. 定时发布中 + 定时触发 → 已发布
        map.put(key(ArticleStatus.SCHEDULED, ArticleAction.PUBLISH_SCHEDULED_TRIGGER), ArticleStatus.PUBLISHED);

        // 10. 已发布 + 撤回 → 已撤回
        map.put(key(ArticleStatus.PUBLISHED, ArticleAction.WITHDRAW), ArticleStatus.WITHDRAWN);
        // 11. 已发布 + 下架 → 已下架
        map.put(key(ArticleStatus.PUBLISHED, ArticleAction.OFFLINE), ArticleStatus.OFFLINE);

        // 12. 已撤回 + 立即发布 → 已发布（改完重新上）
        map.put(key(ArticleStatus.WITHDRAWN, ArticleAction.PUBLISH_NOW), ArticleStatus.PUBLISHED);

        // 13. 已撤回 + 归档 → 已归档
        map.put(key(ArticleStatus.WITHDRAWN, ArticleAction.ARCHIVE), ArticleStatus.ARCHIVED);
        // 14. 已下架 + 归档 → 已归档
        map.put(key(ArticleStatus.OFFLINE, ArticleAction.ARCHIVE), ArticleStatus.ARCHIVED);

        TRANSITIONS = Collections.unmodifiableMap(map);
    }

    private static String key(ArticleStatus status, ArticleAction action) {
        return status.name() + ":" + action.name();
    }

    /** 判断某状态下能否执行某动作 */
    public static boolean canTransfer(ArticleStatus status, ArticleAction action) {
        if (status == null || action == null) {
            return false;
        }
        return TRANSITIONS.containsKey(key(status, action));
    }

    public static boolean canTransfer(Integer statusCode, ArticleAction action) {
        return canTransfer(ArticleStatus.of(statusCode), action);
    }

    /**
     * 计算目标状态。合法则返回目标，非法直接抛 BusinessException。
     * 业务代码只需："我要提交这篇文章" → transfer(当前状态, SUBMIT)。
     */
    public static ArticleStatus transfer(ArticleStatus status, ArticleAction action) {
        if (status == null) {
            throw new BusinessException(ErrorCode.ARTICLE_NOT_FOUND);
        }
        if (status.isFinal()) {
            throw new BusinessException(ErrorCode.ARTICLE_ARCHIVED_READONLY,
                    "文章已归档，不可再执行任何操作");
        }
        String k = key(status, action);
        ArticleStatus target = TRANSITIONS.get(k);
        if (target == null) {
            throw new BusinessException(ErrorCode.ARTICLE_STATUS_ILLEGAL,
                    String.format("文章当前状态为「%s」，不允许执行「%s」",
                            status.getDescription(), action.getDescription()));
        }
        return target;
    }

    public static ArticleStatus transfer(Integer statusCode, ArticleAction action) {
        return transfer(ArticleStatus.of(statusCode), action);
    }

    /** 返回全部合法迁移，供测试与文档校验 */
    public static Set<String> allTransitions() {
        return TRANSITIONS.keySet();
    }
}
```

### 6.4 状态机使用方式（Service 层）

```java
@Override
@Transactional(rollbackFor = Exception.class)
public void submit(Long articleId, LoginUser user) {
    Article article = articleMapper.selectById(articleId);
    if (article == null) {
        throw new BusinessException(ErrorCode.ARTICLE_NOT_FOUND);
    }
    // 1. 水平越权校验：只能提交自己的文章
    checkOwnership(article, user);
    // 2. 状态机校验 + 计算目标状态（不合法直接抛异常）
    ArticleStatus target = ArticleStateMachine.transfer(article.getStatus(), ArticleAction.SUBMIT);
    // 3. 落库
    article.setStatus(target.getCode());
    article.setUpdateBy(user.getUserId());
    if (articleMapper.updateById(article) == 0) {
        // 乐观锁失败：说明有人抢先改了
        throw new BusinessException(ErrorCode.ARTICLE_UPDATE_CONFLICT);
    }
}

private void checkOwnership(Article article, LoginUser user) {
    if (Boolean.TRUE.equals(user.getSuperAdmin())) {
        return;
    }
    if (!article.getAuthorId().equals(user.getUserId())) {
        throw new BusinessException(ErrorCode.ARTICLE_NOT_OWNER);
    }
}
```

> **注意 `updateById` 返回 0 的含义**：MP 的乐观锁插件在 `version` 不匹配时会返回 0（不更新），**不抛异常**。所以必须显式判 0 并抛 `ARTICLE_UPDATE_CONFLICT`，否则会静默失败 —— 这是 MP 乐观锁最常见的坑。

## 七、HTTP 请求约定汇总

| 项 | 约定 |
|---|---|
| Content-Type（写操作） | `application/json;charset=UTF-8` |
| Content-Type（文件上传） | `multipart/form-data` |
| 字符集 | 全链路 UTF-8（连接串 `characterEncoding=utf8`、响应 `charset=UTF-8`） |
| 时间格式 | 请求/响应统一 `yyyy-MM-dd HH:mm:ss`（Jackson 全局配置） |
| 时间类型 | Java 侧统一 `LocalDateTime`（不用 `Date`） |
| 日期格式 | `yyyy-MM-dd` |
| 空值处理 | Jackson 不输出 `null` 字段（`NON_NULL`），前端少判空 |
| 数值 | `Long` 超 15 位可能丢精度 → 前端 axios 配 `json-bigint`（本项目 id 不会超，但要留注释说明） |
| 分页参数 | `page`（从 1 开始）、`size`（≤100）、`sortField`、`sortOrder` |
| 登录态 | Session（`JSESSIONID` Cookie），超时 30 分钟 |

**Jackson 全局配置（主干提供）**

```java
package com.lab.cms.config;

import com.fasterxml.jackson.annotation.JsonInclude;
import com.fasterxml.jackson.databind.ObjectMapper;
import com.fasterxml.jackson.datatype.jsr310.JavaTimeModule;
import com.fasterxml.jackson.datatype.jsr310.deser.LocalDateDeserializer;
import com.fasterxml.jackson.datatype.jsr310.deser.LocalDateTimeDeserializer;
import com.fasterxml.jackson.datatype.jsr310.ser.LocalDateSerializer;
import com.fasterxml.jackson.datatype.jsr310.ser.LocalDateTimeSerializer;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.http.converter.json.MappingJackson2HttpMessageConverter;

import java.time.LocalDate;
import java.time.LocalDateTime;
import java.time.format.DateTimeFormatter;

/**
 * Jackson 全局配置。
 * 目的：① LocalDateTime 正确序列化 ② null 字段不输出 ③ 时间格式统一
 */
@Configuration
public class JacksonConfig {

    public static final String DATE_TIME_PATTERN = "yyyy-MM-dd HH:mm:ss";
    public static final String DATE_PATTERN = "yyyy-MM-dd";

    @Bean
    public MappingJackson2HttpMessageConverter mappingJackson2HttpMessageConverter() {
        ObjectMapper mapper = new ObjectMapper();

        // 1. JSR-310 时间模块
        JavaTimeModule timeModule = new JavaTimeModule();
        DateTimeFormatter dateTimeFormatter = DateTimeFormatter.ofPattern(DATE_TIME_PATTERN);
        DateTimeFormatter dateFormatter = DateTimeFormatter.ofPattern(DATE_PATTERN);

        timeModule.addSerializer(LocalDateTime.class, new LocalDateTimeSerializer(dateTimeFormatter));
        timeModule.addDeserializer(LocalDateTime.class, new LocalDateTimeDeserializer(dateTimeFormatter));
        timeModule.addSerializer(LocalDate.class, new LocalDateSerializer(dateFormatter));
        timeModule.addDeserializer(LocalDate.class, new LocalDateDeserializer(dateFormatter));
        mapper.registerModule(timeModule);

        // 2. null 字段不输出（但要保留空集合，前端遍历更省事）
        mapper.setSerializationInclusion(JsonInclude.Include.NON_NULL);

        // 3. 未知字段不报错（前端多传字段不导致 400）
        mapper.configure(com.fasterxml.jackson.databind.DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIES, false);

        MappingJackson2HttpMessageConverter converter = new MappingJackson2HttpMessageConverter();
        converter.setObjectMapper(mapper);
        return converter;
    }
}
```

> ⚠️ **`JavaTimeModule` 是 Spring 5.3 的必修课**：不注册它，`LocalDateTime` 会序列化成 `[2026,10,8,17,25,42]` 这样的数组，前端完全没法用。这个坑在 Spring Boot 里被自动配置掩盖了，纯 SSM 手写配置必须自己注册。

## 八、跨域（CORS）约定

前端是 Vite 独立开发服务器（默认 `http://localhost:5173`），后端是 Tomcat（`http://localhost:8080`），**开发期必然跨域**。

**方案：后端放开 CORS + 前端配置 proxy，双保险**

```java
package com.lab.cms.config;

import org.springframework.context.annotation.Configuration;
import org.springframework.web.servlet.config.annotation.CorsRegistry;
import org.springframework.web.servlet.config.annotation.WebMvcConfigurer;

/**
 * 跨域配置。
 * 注意：allowCredentials(true) 与 allowedOrigins("*") 不能同时使用，
 * 必须用 allowedOriginPatterns。
 */
@Configuration
public class CorsConfig implements WebMvcConfigurer {

    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/api/**")
                .allowedOriginPatterns("http://localhost:*", "http://127.0.0.1:*")
                .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
                .allowedHeaders("*")
                .allowCredentials(true)   // 带上 JSESSIONID
                .maxAge(3600);
    }
}
```

**前端 `vite.config.js` 里的 proxy（推荐用这个，更稳）**

```javascript
server: {
  port: 5173,
  proxy: {
    '/api': {
      target: 'http://localhost:8080',
      changeOrigin: true
      // 不做 rewrite：后端 URL 本身就带 /api/v1 前缀
    }
  }
}
```

> **两种方式都要保留**：proxy 用于本地开发（同源，无 Cookie 问题），CORS 配置用于"前端独立部署后直连后端"的场景（如答辩时用 `npm run build` 出的静态包 + Tomcat）。只做一种，到部署环节会返工。
